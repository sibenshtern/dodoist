# ADR-002: Интеграция Django Admin

**Статус:** Принято

---

## Контекст

В проекте отсутствовал интерфейс для просмотра и редактирования данных в базе напрямую. В ходе разработки и отладки это вынуждало использовать `django shell`, прямые SQL-запросы или внешние инструменты (DBeaver, psql). При добавлении новых доменных моделей (аналитика, уведомления, вложения) проблема усугублялась.

Рассматривались варианты:

| Вариант | Описание |
|---|---|
| Django Admin | Стандартный встроенный интерфейс Django |
| django-grappelli / Jazzmin | Сторонние темы поверх Django Admin |
| Самописный интерфейс | Собственные вьюхи для управления данными |

---

## Решение

Мы подключим стандартный **Django Admin** (`django.contrib.admin`) и зарегистрируем в нём все модели трёх приложений: `users`, `projects`, `tasks`.

Все модели регистрируются через `admin.ModelAdmin` (не `BaseUserAdmin`), так как кастомная модель `User` не использует стандартные группы и разрешения Django.

---

## Последствия

**Положительные:**
- Мгновенный доступ к данным через браузер без написания кода
- Удобен для ручной верификации функционала во время разработки
- Не требует сторонних зависимостей — Django Admin входит в стандартную поставку

**Отрицательные:**
- Потребовалось добавить в `INSTALLED_APPS` вспомогательные приложения: `django.contrib.sessions`, `django.contrib.messages`, `django.contrib.staticfiles`
- Необходимо добавить соответствующий middleware и настройку `TEMPLATES` с `context_processors`
- Для production-окружения необходимо дополнительно ограничить доступ к `/admin/` на уровне сетевой конфигурации
