# ADR-010: Полнотекстовый поиск по задачам

**Статус:** Принято

---

## Контекст

Пользователи должны иметь возможность искать задачи по ключевым словам в заголовке и описании. Текущая реализация использует простое сравнение по подстроке (`ILIKE`), которое не учитывает морфологию, работает медленно на больших объёмах данных и не поддерживает ранжирование результатов.

Рассматривались варианты:

| Вариант | Описание |
|---|---|
| `ILIKE` (текущее) | Простое совпадение по подстроке, без индексирования |
| PostgreSQL FTS | Встроенный полнотекстовый поиск: `tsvector`, `tsquery`, GIN-индекс |
| Elasticsearch / OpenSearch | Выделенный поисковый движок |
| Meilisearch | Простой self-hosted поисковый сервис |

---

## Решение

Мы будем использовать **встроенный полнотекстовый поиск PostgreSQL** (`tsvector` + `tsquery` + GIN-индекс по полям заголовка и описания задачи). Результаты сортируются по релевантности (`ts_rank`).

---

## Последствия

**Положительные:**
- Нет новых инфраструктурных зависимостей — используется та же БД
- Поддержка стемминга и морфологии через конфигурации языка
- Значительно быстрее `ILIKE` на больших таблицах за счёт GIN-индекса
- Ранжирование результатов по релевантности

**Отрицательные:**
- Менее гибкий, чем Elasticsearch: нет фасетного поиска, опечаткоустойчивости и синонимов из коробки
- Индекс нужно обновлять при изменении данных (поддерживается триггерами или `UPDATE` на поле `tsvector`)
- Ограниченная поддержка русского языка без установки дополнительных словарей (`pg_catalog.russian`)
