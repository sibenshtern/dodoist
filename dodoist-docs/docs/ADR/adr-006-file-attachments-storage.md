# ADR-006: Хранилище файловых вложений

**Статус:** Принято

---

## Контекст

Пользователи должны иметь возможность прикреплять файлы к задачам и комментариям. Файлы могут быть изображениями, документами, архивами — размером до 50 МБ. Нужно обеспечить надёжное хранение, безопасную выдачу и возможность удаления.

Рассматривались три варианта:

| Вариант | Описание |
|---|---|
| Хранить в базе данных (BLOB) | Файлы как бинарные поля в таблице |
| Локальная файловая система сервера | Файлы в директории на диске |
| Внешнее объектное хранилище (S3-совместимое) | Файлы в облачном бакете |

---

## Решение

Мы будем хранить файлы во **внешнем объектном хранилище** (S3-совместимом API). В базе данных хранится только метаинформация: имя файла, размер, MIME-тип и ключ пути в хранилище. Доступ к файлам предоставляется через **предподписанные URL** с временем жизни 1 час.

---

## Последствия

**Положительные:**
- База данных не раздувается от бинарных данных
- Файловый трафик идёт напрямую между клиентом и хранилищем, минуя сервер приложений
- Горизонтальное масштабирование: несколько инстансов приложения работают с одним бакетом
- Предподписанные URL ограничивают доступ по времени без дополнительной авторизации на сервере

**Отрицательные:**
- Новая внешняя зависимость (S3 или совместимый сервис)
- В локальной разработке нужна эмуляция (например, MinIO или `django-storages` с `FileSystemStorage`)
- Удалённые из БД записи не автоматически удаляют файл из бакета — нужна отдельная задача очистки
