# ADR-009: Курсорная пагинация списковых эндпоинтов

**Статус:** Принято

---

## Контекст

Большинство списковых эндпоинтов API (задачи, комментарии, уведомления, журнал активности) могут возвращать тысячи записей. Без пагинации запросы будут медленными и создавать чрезмерную нагрузку на базу данных.

Рассматривались два подхода к пагинации:

| Подход | Описание |
|---|---|
| Страничная пагинация (`page` + `limit`) | Клиент запрашивает конкретную страницу по номеру |
| Курсорная пагинация (`cursor` + `limit`) | Клиент получает непрозрачный курсор для запроса следующей порции |

---

## Решение

Мы будем использовать **курсорную пагинацию**. API возвращает непрозрачный курсор в поле `meta.next_cursor`; клиент передаёт его в следующем запросе для получения следующей порции записей. Если `next_cursor` равен `null` — записи закончились.

---

## Последствия

**Положительные:**
- Стабильные результаты при вставке или удалении записей между запросами (нет «прыжков» страниц)
- Нет проблемы «пропущенных» или «задвоенных» записей при частом обновлении данных
- Эффективно работает с индексами по `created_at` или `id` — без `OFFSET`, который замедляется на больших таблицах

**Отрицательные:**
- Нельзя перейти на произвольную страницу — только «вперёд»
- Нельзя показать пользователю общее количество страниц
- Чуть сложнее реализовать на бэкенде и клиенте по сравнению с offset-пагинацией
