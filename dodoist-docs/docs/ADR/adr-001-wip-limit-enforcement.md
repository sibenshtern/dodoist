# ADR-001: Принудительное соблюдение WIP-лимита на колонке доски

**Статус:** Принято

---

## Контекст

Модель данных `BoardColumn` содержит поле `wip_limit` — максимальное количество задач, которые могут одновременно находиться в колонке. Это стандартная практика канбан-методологии для контроля объёма незавершённой работы.

До Phase 0 поле существовало только как атрибут данных: при перемещении задач в колонку никакой проверки не происходило. Ограничение можно было нарушить без каких-либо последствий.

---

## Решение

Мы будем проверять `wip_limit` на уровне сервисного слоя при каждом перемещении задачи в колонку. Если лимит превышен, операция отклоняется.

HTTP-эндпоинт возвращает `409 Conflict` — не `400 Bad Request`, потому что запрос синтаксически корректен, но конфликтует с текущим состоянием ресурса.

---

## Последствия

**Положительные:**
- Данные в базе соответствуют заявленным ограничениям системы
- Поведение предсказуемо: пользователь получает явную ошибку вместо молчаливого нарушения правила
- Код проверки находится в сервисном слое и не дублируется по вьюхам

**Отрицательные:**
- Пользователь не может переместить задачу, пока не освободит место в колонке — в ряде сценариев это может быть неудобно
- Задачи, перемещаемые «внутри» той же колонки (например, drag-and-drop для изменения порядка), должны явно исключаться из подсчёта, иначе операция будет ошибочно блокироваться
