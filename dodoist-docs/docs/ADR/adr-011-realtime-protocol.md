# ADR-011: Протокол обновлений в реальном времени

**Статус:** Принято

---

## Контекст

Пользователи должны видеть новые уведомления без перезагрузки страницы. В идеале — изменения статуса задач и новые комментарии тоже должны появляться мгновенно для всех участников.

Рассматривались варианты:

| Вариант | Описание |
|---|---|
| Периодический polling | Фронтенд опрашивает API каждые N секунд |
| Long polling | Запрос висит открытым до появления новых данных |
| Server-Sent Events (SSE) | Сервер отправляет события через постоянное HTTP-соединение |
| WebSocket | Двунаправленное постоянное соединение |

---

## Решение

Мы будем использовать **Server-Sent Events (SSE)**. Сервер поддерживает открытое HTTP-соединение и отправляет события в браузер по мере их появления. До реализации SSE в качестве временного решения используется polling с интервалом 60 секунд.

WebSocket рассматривался как альтернатива, однако для нашего use case (сервер → клиент) его двунаправленность избыточна.

---

## Последствия

**Положительные:**
- Простота по сравнению с WebSocket: SSE работает поверх обычного HTTP, не требует специального обработчика протокола
- Встроенная поддержка в браузерах через `EventSource` API
- Автоматическое переподключение при обрыве соединения — браузер делает это сам
- При сбое SSE фронтенд прозрачно переходит на polling без потери функциональности

**Отрицательные:**
- Однонаправленность: если в будущем понадобится отправлять данные с клиента в реальном времени, SSE не подойдёт
- Каждый открытый SSE-поток держит соединение с сервером — нагрузка на воркеры при большом числе одновременных пользователей
- Ограничение браузеров: не более 6 одновременных HTTP/1.1 SSE-соединений на один хост
