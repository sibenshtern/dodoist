# ADR-003: Выбор родительской задачи через typeahead

**Статус:** Принято

---

## Контекст

Форма создания задачи содержала поле `parent_task_id`, в которое пользователь вводил UUID родительской задачи вручную. Это неудобно: UUID не читаем, нет подтверждения существования задачи до сохранения, нет связи поля с выбранным проектом.

Рассматривались варианты:

| Вариант | Описание |
|---|---|
| Свободный ввод UUID | Текущее состояние — минимально, но неудобно |
| Серверный autocomplete | Отдельный эндпоинт для поиска задач по подстроке в заголовке |
| Клиентская фильтрация | Загрузить задачи проекта заранее, фильтровать на фронтенде |

---

## Решение

Мы будем использовать **клиентскую фильтрацию**: при выборе проекта в форме фронтенд загружает список задач проекта через `GET /api/projects/{id}/tasks/` и сохраняет его в памяти компонента. При вводе в поле поиска задачи фильтруются по подстроке в заголовке; выбранный результат записывает `task.id` в управляющий `FormControl`.

Серверный autocomplete не реализуется на этом этапе, так как объём задач в одном проекте достаточно мал для комфортной клиентской фильтрации.

---

## Последствия

**Положительные:**
- Пользователь видит задачи в контексте выбранного проекта и не может случайно выбрать задачу из другого проекта
- Нет дополнительных HTTP-запросов при вводе каждого символа — список загружается один раз
- UUID родительской задачи записывается автоматически; пользователь оперирует читаемыми названиями

**Отрицательные:**
- При большом количестве задач в проекте (сотни и тысячи) список будет загружаться полностью — потенциальная нагрузка на API и память браузера
- При переключении проекта список сбрасывается и загружается заново
- Серверный поиск с `PostgreSQL FTS` (Phase 8) даст более точные результаты по морфологии, но для выбора родительской задачи это некритично
